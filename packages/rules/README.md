# Local puzzle rules

This package is a pure TypeScript rules slice. It works on the v1 definition and snapshot supplied by the caller; it does not save a game, communicate previews, manage leases, authorize a player, or serialize competing requests. `begin` checks contract shape, membership, connected groups and reversed adjoining contours. Import must independently verify the definition checksum, full contour validity, and authoritative identity/day. The caller owns synchronization, IDs, leases, preview generations, collision policy and an atomic durable commit. In particular, this slice does **not** implement contour overlap or claim that its result is sufficient for accepting a public server command.

Call `begin(definition, snapshot, allowance)` for a draft, then `move` with a unique action ID to start an action or the existing ID to readjust it. Each operation returns a new draft; rejected operations throw `RuleError` without changing the input. `preview` returns touched groups, never a canonical board. Rotation is clockwise in millidegrees: settled transforms use 0, 90000, 180000 or 270000, and `rotateAround` accepts quarter-turn multiples about a visible pivot. Legacy boards with other orientations remain inspectable via `begin`, but interaction rejects with `UNSUPPORTED_LEGACY_ORIENTATION`; no migration is performed. See the [generator documentation](../generator/README.md) for initial orientations. Repeated adjustment does not consume another slot. The UI should send a chosen transform, not rely on local pointer coordinates as proof of a path.

`attach` requires different adjacent groups and a new UUID; both groups must be reserved by the service. It compares the orientation difference (shortest circular angle) and Euclidean displacement of a moving adjacent piece's reference point under the two transforms, using inclusive caller-provided distance and angle tolerances. If accepted it uses the target's exact transform for the merged group; it does not approximate a match or align non-neighbors. Tolerances must be fixed by the trusted service, not chosen by an untrusted client. These are explicit local semantics, not yet a cross-language or frontend-approved tolerance or collision rule. Movement checks every piece's reference point against the half-open workspace; it does not check entire contours against the workspace boundary.

`pendingCount` derives provisional cost from canonical group history, zone, current geometry and joins. An outer loose sort is free; entry is charged, and returning an unjoined entry outside demotes it. Each separately introduced action keeps its own charge after a join; a free outer action is charged if it subsequently enters, including during a snap. A snap that moves a separately controlled component is charged independently of the target's actions. Moving a joined group with no paid action costs one move when it involves the canvas or an already confirmed connected group. A previously confirmed connected group is one action. A single-source action ending at its original transform is free. At most the supplied remaining allowance can be pending, but existing actions remain adjustable. Undo increments the draft generation when successful; see the [shared contract](../contracts/README.md) for joined-action behavior. The transport owner must fence the old generation and re-emit surviving overlays. Cancellation returns the **latest** caller-supplied snapshot, not the draft's old base.

`confirm` checks the latest touched groups and allowance and returns a proposed snapshot and allowance, leaving its inputs unchanged. An unrelated newer group remains intact; a touched-group conflict or quota change rejects the entire result. A service must repeat these checks and apply the result, version, quota, event and idempotent command outcome in one transaction; this function alone makes no durability or concurrency guarantee. No-op-only batches do not advance the version. The caller must clear previews in coordination with the actual commit outcome. `finalPosition` is recomputed for changed groups from the exact identity transform; pre-completion groups remain movable.

Run `pnpm --filter @world-jigsaw/rules test` and `pnpm --filter @world-jigsaw/rules typecheck`. Tests consume the real seeded 60- and 80-piece fixtures and assemble them using multiple hypothetical players. `vectors/behavior.json` records portable arithmetic and accounting expectations; the existing `packages/contracts/v1/fixtures` contain further wire and scenario vectors. Floating-point trigonometry uses JavaScript double precision and `floor(x + 0.5)` rounding; exact cross-language behavior near rounding boundaries needs an agreed numerical implementation before production use.
